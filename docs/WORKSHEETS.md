# A05 — worksheets for educators' own materials

Development verification, 2026-11-16. **Learn → Create worksheet** authors an explicit export from configured tree questions, inheritance setups or population setups. It does not generate a course, infer relationships/traits or track learners. Application guides remain here; the [education companion workflow](https://github.com/EliVHD/phyloink-education/tree/codex/worksheet-workflow/worksheet-export) adapts existing examples rather than adding another lesson collection.

## Authoring and printing

In tree practice, choose the current question (including unkept setup edits) or up to 12 kept questions. A valid biological root and 2–16 exact source tips are required as before. In a synthetic lab, use the current parent/population parameters, size/horizon and seed. Setups are captured independently of current predictions, feedback, sample DOM or answer selections.

Edit the title (500 characters), student instructions and teacher-only notes (10,000 each), and prompts (5,000 each). Choose A4 or Letter, 2–8 blank answer lines, optional tip codes and optional seed-derived lab data. Changing scope resets worksheet prompts; worksheet edits do not change Learn setups. Prepare a static preview, inspect both audiences, then download their ZIPs separately. Closing/editing invalidates pending font measurement/preparation and pending downloads; no discarded result becomes a worksheet or document edit.

Open `student.html` or `teacher.html` locally and use browser Print / Save as PDF at 100% scale on the selected paper. Exported files need no server, script or external asset. Plain-text questions and native SVGs remain editable. Long prompts or reference tables may span pages; print preview remains the final check. Tree question figures use measured physical font sizes and reject if their bounds exceed the paper instead of silently scaling labels. Use codes, a smaller sample or explicit shorter display labels when necessary. Draft font/geometry findings remain printed and recorded. Font measurements apply to the export browser; review on the intended printing device.

## Audience and state boundaries

Student packages contain worksheet HTML/plain text, applicable SVG/data/source files, `context.json`, README and exact manifest. They omit the teacher reference, educator notes, teacher authoring record and teacher-only population reference plot. Teacher packages contain the separately named teacher HTML/plain text and `authoring.json` with edited prompts/options/notes. Keep them separate from student distribution. Underlying source/model data remain available for reasoning; this is not a secure assessment system.

Configured source/model references are computed independently of learner responses. They follow the configured task/setup rather than interpreting custom prose; educators review them and use teacher-only notes for custom answers/adaptations. No learner answers, feedback, progress, selected highlights, editor artwork, reference pictures or project/history state enter either package. Snapshot preparation and export preserve dirty/saved editor state, artwork, source/reduction/scientific context, pins, selection, camera, QA and undo. Worksheet drafts are discarded on return to the editor.

This explicit export may retain educator lab parameters/seeds and regenerate data; it does not change tree-scenario V1 or project V4 persistence. `phyloink-worksheet-context` and teacher `phyloink-worksheet-authoring` V1 are export records, not new application import/scenario formats. There is no worksheet reimport/autosave or continuing content programme. Teachers can edit HTML/plain text/SVG externally; those edits invalidate the old payload hashes.

## Source/model and export integrity

Tree setups pass the existing scenario/source/identity/citation validation. Figures are reconstructed with shared browser font measurement and source-preserving layout; they never serialize the interactive SVG, learner overlays or feedback. Complete child-subtree rotations, polytomies, duplicate identities and exact original edge paths/memberships survive. Static numbered nodes and full-name/source-ID legends support questions; declared virtual root junctions are distinguished from original source identities. Ancestor/clade references disclose full-source versus displayed/omitted descendants. Every figure's scene revision, measurements and QA are recorded.

`source.nwk` retains supplied UTF-8 text including BOM/CRLF, protected source citations/rights, display-only corrections and the original hash basis. Hashes are checked again before packaging. Unknown rights/citations remain explicit; user-authored text and data are not automatically relicensed as template software. Original template/software is 0BSD. No source/reference URL is fetched automatically.

Inheritance worksheets use the existing model to regenerate complete genotype/phenotype sample counts from educator parents, size and seed. Expected probabilities/counts are in the teacher reference. Population student plots show complete finite trials; teacher plots add the no-drift reference with its existing limitations. Printed tables explicitly select generation 0, midpoint and final; `population-counts.csv` preserves every trial/generation, with exact integer counts. Disabling data omits those samples/plots/CSV while retaining setup/model context. Scientific/model limits and assumptions remain visible.

Artifact paths are allowlisted. Each package's `phyloink-worksheet-package` V1 manifest identifies audience, renderer `worksheet-v1`, exact payload inventory, UTF-8 byte sizes, SHA256 hashes and build identity. Original source hashes are independent of template/build hashes. Payloads above 30 MB reject before ZIP creation; context serialization also has a 30 MB work bound. Repeated source-membership records are capped at 1,000,000 entries across figures; exceeding the bound rejects rather than pruning identities. Use a smaller source or fewer questions. HTML has no executable scripts or embeds; author/source text is escaped and a restrictive content policy permits only the built-in inline styles. Preview runs in a sandboxed iframe. No runtime dependency, dataset, external artwork or change to published releases is introduced.
