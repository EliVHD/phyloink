The complete distribution is a collection with component-specific terms, not a blanket relicensing of all files.

## Release procedure

Run `npm run release`. It builds, tests and creates two archives under `outputs/releases/`: a browser bundle and a source bundle. Each contains a `release-manifest.json` mapping every other file to its SHA256, byte count, component and applicable license expression. The manifest excludes itself. These are application-specific inventories, not certified SPDX/CycloneDX SBOMs or a legal opinion.

The browser bundle contains the complete static application, its required data and notices; serve it over HTTP, including loopback for offline use. It does not embed a browser or Node runtime. The source bundle contains the source, tests, locked build definitions and required test data. `npm ci` obtains development tools separately; an initial source build needs those downloads or a prepared dependency cache. The source archive's README describes the commands. A bundle with the compiler, Node executable or installer would be a new distribution profile needing its own inventory and notice review.

`release/components.json` is the reviewed input list. New source modules, bundled assets or a changed dependency lock must be reviewed before a release succeeds. Hash-pinned upstream inputs cannot silently change. Planned resources are not counted as present just because a paper or library is cited. Do not ZIP the entire working directory: private references, old project exports and screenshots remain outside the release.

The build stamp identifies the exporting software. Version-2 projects separately retain accepted-operation builds and per-component contributions, and tree exports include Sources & Methods and reference files. Migration preserves unknown earlier history without inferring operations from stored fit controls. The new model, registries, serializer, schema and synchronous content hashing are original application code; no new third-party runtime package, paper figure or external algorithm source code was bundled. The material-authoring workflow, structured layouts and local-file search are implemented. Online/provider and biology-analysis extensions are outside the active scope.

For future work, prefer an independent implementation or a suitable permissive dependency when it meets the technical need. Record whether third-party material is copied, linked, bundled as data, fetched separately or cited only, and the resulting obligations. If a necessary component brings broader conditions, assess those conditions before integrating it. Do not add our own restrictions to compensate for uncertainty or label unreviewed material unrestricted.
